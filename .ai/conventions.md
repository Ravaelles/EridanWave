# Working conventions

1. **English for code, user's language for communication.** 100% of code and code comments is written in English: identifiers, comments, commit messages, and documentation diagrams. Communication with the user happens in the language the user uses in their prompt.
2. **Pragmatic understanding, not perfectionist understanding.** We always aim to understand the source of a problem before fixing it, but we never chase exhaustive understanding. Prefer the smallest investigation that unblocks a confident fix and minimizes long-term maintenance cost.
3. **Speak up with a better idea.** If you believe there is a better solution than what was asked for, say so and propose it. Never blindly execute a sequence of steps; recommend the best solution and wait for confirmation when the direction is materially different.
4. **Follow SOLID.** In particular, take Single Responsibility Principle (SRP) and Open/Closed Principle (OCP) seriously: one reason to change per unit, and extend behavior through new code rather than by modifying existing code.
5. **Rebuild the bot jar at the end of the work.** When you send the final message for a task, run `scripts/build-jar.sh` first (incremental, skips when nothing changed) so the owner never waits on a cold rebuild for the next game start.
6. **Commit each finished feature as a coherent whole.** After completing a functionality that forms a consistent unit, commit it. A commit must never contain documentation or text-only changes by themselves; docs and comments ride along as part of the feature they describe. You may freely commit changes you did not author as long as they belong to the committed whole.
7. **Test through the build tool, next to the code by convention.** Unit tests live in `src/test/scala`, mirroring the `src/` tree one `*Suite` per unit (ScalaTest FunSuite), and run with `mvn -Ptests test`. Do not co-locate test files with production files: the build owns the layout, and it keeps test code out of the shipped fat jar. Prefer testing pure decision logic behind a thin game-aware seam (see `HuntLogic`/`KillLedger.record`); follow TDD for complex rules. The legacy `tests/` folder (standalone Apps run by hand) is grandfathered - leave it alone.
8. **Blank lines around `return` are gated, nothing else is.** Run `python3 scripts/check-blank-lines.py` on touched files before committing (rules in `tools/blank-lines.xml`, ported from Atlantis `tools/checkstyle.xml`: blank after a `return`, blank before a final `return`). Do not reformat untouched legacy code to satisfy it - fix only your own new violations, same as Atlantis skips its Indentation/EmptyLineSeparator churn.
9. **Noisy per-frame diagnostics go through the keyed ledger, not raw log spam.** `Debugging.ErrorLedger.note(key, priority, message)` with a stable greppable key (`area.Cause.at.Place:line`) instead of repeating full traces every frame; query token-cheap with `python3 scripts/summarize-errors.py <errors.json> [--min-priority medium] [--key ...]` (one line per key, worst first). Exceptions are funneled automatically via the logger.
10. **Split until it reads like prose (SRP).** When touching a class, break methods that do more than one thing into small named methods, and extract tangled multi-level conditions into predicates with intention-revealing names: `outrunnableThreat(group, enemy)` instead of a five-line boolean expression. New code must read in natural language. Never reformat untouched legacy code to satisfy this - apply it to code you modify, one method at a time, without forcing it.
